- [Phases 1][CMIC-API] FR-03.1: Customer Preference...

## Strict rules
- DO NOT guess, assume, or infer anything that is not explicitly stated in the document or verifiable in the code.
- If something is mentioned in the document and may exist in the code (entities, tables, APIs, configs, enums, status codes, services), SEARCH the codebase and cite what you find.
- If the document references another BRD section, term, or rule that is not in this file, try to find it in the code first. If it still cannot be confirmed, record it as a question. Do not explain it from assumption.
- If, after reading the document AND searching the code, something is still unclear, ambiguous, missing, or contradictory, DO NOT fill the gap yourself. Put it in the questions file.
- If the document and the code disagree, do not decide which is correct. Record it as a question.
- Every statement in the explanation file must have a source:
  - Document: section number/title (and table/figure name if applicable)
  - Code: file path + class/method name
- Use plain, simple English. Explain business terms the first time they appear.

## Process
1. Read `[BRD_focus.docx]` fully, section by section.
2. For each section, identify: purpose, actors, inputs, outputs, business rules, validations, flows, exceptions, and dependencies on other sections.
3. List every reference to content outside this file (other FRs, stories, glossary terms, external systems).
4. For every technical element and external reference, search the codebase and note whether it exists, partially exists, or does not exist yet.
5. Classify each finding as either "Clear" (go to file 1) or "Unclear" (go to file 2). Nothing may be left unclassified.
